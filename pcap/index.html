One capture of a plaintext HTTP login that leaks three secrets — each a level harder to read. Open it in Wireshark or read it with tshark. Full answers in solution.md.

File: http_login_cleartext.pcap — TCP handshake + a POST /login and its response.

1 · The cleartext form login 🟢 Easy

Identify the protocol/port and recover the username & password from the form body.

💡 starter command 
tshark -r http_login_cleartext.pcap
tshark -r http_login_cleartext.pcap -z follow,tcp,ascii,0 -q   # or Wireshark: Follow → TCP Stream

2 · The Basic-auth header 🟡 Medium

The request also carries Authorization: Basic … — recover the credential inside it.

💡 starter command 
tshark -r http_login_cleartext.pcap -Y http.request -T fields -e http.authorization
echo '<the base64>' | base64 -d        # Basic auth = base64(user:pass), not encryption

3 · The session token 🟠 Hard

Decode the server's Set-Cookie: session=…. What's inside, and why is it insecure?

💡 starter command 
tshark -r http_login_cleartext.pcap -Y http.response -T fields -e http.set_cookie
echo '<the base64>' | base64 -d        # base64 JSON, no signature → forgeable

4 · Full reconstruction & impact 🔴 Expert

Client/server IPs, host, URL, all three secrets, and a one-line risk + fix.

💡 starter command 
tshark -r http_login_cleartext.pcap -Y http.request -T fields -e ip.src -e ip.dst -e http.host -e http.request.uri
